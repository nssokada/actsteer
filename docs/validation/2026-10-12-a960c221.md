## Scope and results

Each production checkpoint passed native chat/named-span rendering, plain-text
rendering, layer/token selectors, baseline logits and deterministic generation,
pre/post residual capture, calibration and total-budget scaling, zero-strength
and inactive-mask equivalence, single/multiple-layer selectivity, encode-release,
response-only and continuous windows through cached generation, hook cleanup
including forced exceptions, baseline restoration, and immutable artifact reload
with deterministic reuse. The JSON summary enumerates all 20 checks.

The real runs used instruction-tuned checkpoints in chat mode. Plain-text
rendering was checked, but base-model weights were not tested. Other model
revisions, family variants, precisions, quantization modes, and H200 hardware do
not inherit this validation. Seeded Gaussian directions test instrumentation;
this record establishes no scientific effect or behavioral quality claim.

Local CPU evidence is separate: **41 unit tests passed**, Ruff passed, Pyright
reported **0 errors and 0 warnings**, the configuration CLI passed, all **six**
random tiny-model fixtures (Gemma 2/Llama/Qwen 2 × chat/text) passed 20/20 checks,
and fixture evidence was correctly rejected by real-checkpoint acceptance.
A wheel built from a clean Git export passed the same 41 unit tests. These
checks preceded the successful GPU run; the local audit did not rerun inference.

## Reproduction

Follow the [HPC instructions](../validation.md#reproduce-the-validated-hpc-run)
for checkout, pinned dependencies, authorized checkpoint download, and submission.
Use the exact tested SHA above, a clean checkout, a fresh results directory
outside the checkout, and the documented `sbatch --output` override. The pinned
wrapper runs these model commands followed by aggregate acceptance:

```bash
for family in gemma llama qwen; do
  python -m actsteer.validation.smoke --family "$family" \
    --manifest configs/validation-models.json --output "$ACTSTEER_RESULTS/$family"
done
python -m actsteer.validation.accept --sha "$ACTSTEER_SHA" \
  --manifest configs/validation-models.json --output "$ACTSTEER_RESULTS/acceptance.json" \
  "$ACTSTEER_RESULTS/gemma/report.json" "$ACTSTEER_RESULTS/llama/report.json" \
  "$ACTSTEER_RESULTS/qwen/report.json"
```

For the separate local CPU suite, from the tested checkout with its Python
environment activated:

```bash
bash scripts/validate-local.sh runs/local-validation
```

Use a new output directory. See the [validation guide](../validation.md) for
installation and the differences between fixture and real-checkpoint acceptance.

import json
import os
from pathlib import Path

from actsteer.validation.accept import accept

sha = "a960c22107d720cfc515e00b45c126c184135559"
root = Path(os.environ["ACTSTEER_RESULTS"]).resolve()
reports = []
for family in ("gemma", "llama", "qwen"):

models = json.loads(Path("configs/validation-models.json").read_text())["models"]
result = accept(reports, models, sha)
assert result == json.loads((root / "acceptance.json").read_text())
print(json.dumps(result, indent=2))
